# sample_data/

RAG Support Assist のデモ・動作確認用に同梱しているダミー文書一式です。
いずれも架空の EC カスタマーサポート業務を想定して作成したサンプルで、実在する個人・企業・取引の情報は含みません。

## 収録ファイル

| ファイル | カテゴリ | 概要 |
|---------|---------|------|
| [`faq.txt`](./faq.txt) | FAQ | 注文キャンセル・返品・配送指定・ポイント有効期限・支払い方法など、問い合わせ上位を想定した Q&A 集 |
| [`terms.txt`](./terms.txt) | 利用規約 | 返品/返金ポリシー、配送、ポイントプログラム、アカウント、免責事項、個人情報の取り扱いを定めた条文 |
| [`manual.txt`](./manual.txt) | オペレーター向けマニュアル | 基本対応フロー、エスカレーション基準、返金対応手順、よくある対応パターン |
| [`history.txt`](./history.txt) | 過去問い合わせ対応履歴 | 返品・配送トラブル・不良品・アカウントなど、カテゴリ別の過去対応ケース集 |

これら 4 文書は、RAG が参照すべき「社内ナレッジ」として最低限そろえておきたい 4 カテゴリ（FAQ / 規約 / マニュアル / 過去履歴）をそれぞれ 1 ファイルずつ代表する構成になっています。

## 投入方法

1. Docker Compose または個別起動で backend / frontend を立ち上げる（詳細はリポジトリルートの [`README.md`](../README.md) を参照）。
2. 管理画面 <http://localhost:3000/admin> にアクセス。
3. 「文書アップロード」から本ディレクトリの各 `*.txt` をアップロードする。
4. 投入後、メイン画面 <http://localhost:3000> から問い合わせを入力し、回答候補・参照根拠が表示されることを確認する。

CLI から API で直接アップロードすることも可能です。エンドポイントの詳細は [`docs/API.md`](../docs/API.md) を参照してください。

## 動作確認用の問い合わせ例

投入後に以下のような問い合わせを入力すると、RAG が各文書を参照して回答候補を生成する様子を確認できます。

| 問い合わせ | 主な参照先 |
|-----------|-----------|
| 注文した商品が届きません。注文番号は A2345 です。 | `faq.txt` + `history.txt` |
| セール品を返品したいのですが可能ですか？ | `terms.txt`（第 1 条 4 項） |
| 届いた商品が壊れていました。返金してください。 | `faq.txt` + `terms.txt` + `manual.txt` |
| パスワードリセットのメールが届きません。 | `faq.txt` + `history.txt`（ケース 005） |
| 5 万円の商品を返金してほしい。 | `terms.txt` + `manual.txt`（高額返金のためエスカレーション推奨） |

より詳しいサンプル問い合わせの一覧はリポジトリルートの [`README.md`](../README.md#サンプル問い合わせ例) を参照してください。

## 注意事項

- 本ディレクトリの文書はすべて **架空のダミーデータ** です。実運用で参照できる内容ではありません。
- 本番環境へ投入する際は、実際の FAQ・規約・マニュアル・対応履歴に差し替えてください。
- 投入前にプロンプトの設計方針も確認したい場合は [`docs/PROMPT_GUIDELINES.md`](../docs/PROMPT_GUIDELINES.md) を参照してください。
